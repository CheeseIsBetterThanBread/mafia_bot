# Добавление нового адаптера

Адаптер должен:

* принимать внешние события
* конвертировать их во внутренние Event
* публиковать их в EventBus
* преобразовывать ответы сервера в желаемый вид 

Утверждается, что текущего разнообразия ответов сервера
(`ResponseBase`, `ResponseWithAlert`, `ResponseWithOptions`) хватает
для описания всех ситуаций, которые могут возникнуть

Для справки:
- `ResponseBase` соответствует простой отправке сообщения в чат
- `ResponseWithAlert` в зависимости от валидности ответа отправляет сообщение или редактирует сохраненное
- `ResponceWithOptions` отправляет сообщение с клавиатурой из выборов

---

## Регистрация обработчиков

Сервер общается с адаптерами через `EventBus`. 
Чтобы получать ответы сервера, нужно подписаться на его возвращаемые типы.
Для этого у `EventBus` есть функция `subscribe(event_type, handler)`, 
но удобнее использовать декоратор `on`

```python
@event_bus.on(ResponseType)
async def base_handler(response: ResponseType):
    if type(response) is not ResponseType:
        return
    
    # handle response
    pass
```

---

## Техническое замечание

`EventBus` устроен таким образом, что обработчик вызовется даже если
входящее событие имеет тип наследника, а не зарегистрированный тип.
Так что со стороны адаптера лучше убедиться, что приходящее событие 
имеет ожидаемый тип

## Валидация адаптера

Рекомендуется проверять поддержку нужных Event 
с помощью [validate.py](../utils/validate.py)

## Рекомендация

При настройке обработчиков для ночных действий / голосования / номинирования,
стоит использовать заготовленные шаблоны в [settings.py](../config/settings.py).

Для того чтобы достать из полученной строки значения, можно воспользоваться [парсером](../utils/parser.py)

---

## Использование нового адаптера

Чтобы переключиться на новый адаптер нужно написать его запуск
подобно функции `run` из [bot.by](../adapters/telegram/bot.py).

Её потом можно будет импортировать в main, где она и запустится
