# Добавление новой роли

Роли описываются в:

```text
config/roles.yaml
```

Настоятельно не рекомендуется менять уже написанные роли, 
потому что тогда придётся менять переменные в коде и тестах

Пример:

```yaml
roles:
  - name: Доктор
    description: Лечит игроков

    night_actions:
      - action: heal
        text: Выберите игрока для лечения
```

---

## Поля

Поля роли имеют следующую структуру

| Поле          | Обязательное | Описание                                     |
| ------------- | ------------ |----------------------------------------------|
| name          | Да           | Название роли (обязательно уникальное)       |
| description   | Да           | Описание роли                                |
| is_mafia      | Нет          | Является ли роль мафией (по умолчанию False) |
| night_actions | Нет          | Ночные действия                              |

Поля ночных действий устроены немного иначе

| Поле          | Обязательное | Описание                              |
|---------------|--------------|---------------------------------------|
| action        | Да           | Название действия                     |
| text          | Нет*         | Текст, который покажется игроку ночью |

Наличие текста требуется только у первого вхождения, `action` с таким именем,
остальные подтягиваются из последнего вхождения

---

## Генерация

После изменения YAML:

```bash
make generate
```

Будут обновлены:

* `roles.py`
* `role_actions.py`

В частности сгенерируется enum `NightAction`,
который следует использовать при работе с ночными действиями в коде

---

## Обработка логики

Обработка ночных действий происходит в:
- [dispatcher.py](../engine/dispatcher.py) в методе `_handle_night_action`
- [night.py](../engine/phases/night.py)
- [night_resolution.py](../engine/services/night_resolution.py)

Проверку победы можно найти в [victory.py](../engine/services/victory.py)

Вероятнее всего, менять что-то надо будет только там

---

## Проверка работы

Тесты под новую роль стоит писать в тестовый файл, зеркальный изменённому

Если изменения действительно затронули только те 4 файла,
то можно использовать урезанную версию цели для тестов:

```bash
make test-core
```
